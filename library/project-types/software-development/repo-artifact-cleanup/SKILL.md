# 仓库临时产物清理

逐个仓库识别临时产物，按证据保留、隔离或删除。默认轮转日志和明确的临时产物；目录名、时间和数量只确定候选，保护项与占用检查决定能否处理。其他位置的一次性脚本只报告整理建议。

## 范围与共用清单

- 优先使用本次指定的仓库目录或清单；否则使用 `SYNC_REPOS_FILE`，再否则查找当前可用 `local-repo-sync` 技能源码旁的 `repos.tsv`。通过技能列表定位或解析本技能真实路径后查找同级 `local-repo-sync`；不可依赖当前工作目录。均不可用时询问清单位置，不扫描整个磁盘。
- 与 `worktree-cleanup` 共用该清单，不另建仓库名单。TSV 每行是仓库绝对路径、remote、基线分支及可选说明；忽略空行和以 `#` 开头的行。按制表符解析并检查缺字段，路径不按空格切分。只把首列作为扫描入口；读取清单不意味着运行同步、提交或 rebase。
- 验证每个入口的 Git 根目录，去重同一工作树；单项无效则记录并继续。只处理清单或本次明确指定的工作树，不自动扩展到其他 worktree 或子模块。
- 读取项目约定和已有清理配置。两种清理技能可共用一份用户指定的清理策略，按仓库分别记录：允许的临时路径、保护路径、任务结束证据来源、最短保留期、允许的动作、隔离位置及保留期、日志保留期。项目有明确策略时优先使用；没有单独配置时采用下述默认策略，不再仅因缺少配置而跳过。策略不与仓库名单重复维护。

## 默认轮转策略

用户请求“扫描 / 看看”时只报告；请求“清理 / 跑一遍”或明确授权定时清理时，可按本节删除已确认的普通过期日志，并隔离符合条件的临时批次，无需逐仓库再次要求配置。明确指定的路径、期限和动作优先于默认值。不要为达到非零数量而放宽文件身份或占用检查。

| 对象 | 发现范围 | 时间与数量规则 |
| --- | --- | --- |
| 普通运行日志 | 仓库内 `log/`、`logs/`、`Logs/` 及 `.artifact/`、`.artifacts/` 中已确认用途的 `.log`、轮转日志 | 最后修改超过 72 小时；或同一目录、同一日志流超过 100 份，最旧的超额项且至少 24 小时未修改 |
| 临时运行批次 | `.artifact/`、`.artifacts/`、`artifact/`、`artifacts/` 下有生成入口与来源证据的临时批次 | 全部后代最后修改超过 72 小时；或同一生成器的同类批次超过 20 份，最旧的超额批次且至少 24 小时未修改 |

- 时间按实际执行时刻减文件 mtime 计算，不从文件名猜日期；恰好达到边界不算“超过”。目录年龄取全部后代的最新时间，不使用目录自身时间。数量按最新修改时间倒序，路径作稳定排序；禁止把不同任务、生成器或日志流混为一个数量池。无法识别分组时仅用时间规则。
- 两个条件是“时间到期 **或** 数量超额”；数量规则的 24 小时下限仍有效。最新或唯一一份不自动豁免时间规则：已过期且未在用的普通日志也应删除。数量规则保留最新额度内的项目；临时批次仍核对结束及恢复用途。被保护的内容计入总数但不能为了凑数量上限而删除。
- 普通可丢弃日志包括服务运行、编译器、构建工具输出；确认其内容类型、没有当前验收 / 恢复用途、没有打开句柄且无活跃写入者后，满足阈值即可直接删除，并记录路径、大小、时间、SHA256、判定依据及删除结果；不要求为每个日志另造任务完成文档或可重现原日志。历史文档提到某次命令或日志路径不自动意味着永久保留，应区分当前验收证据、明确保留要求与过时过程记录。对于临时批次，仍需任务结束证据、生成入口与输入存在；缺任一项则待判断。
- 不按父目录名整体判断保护：同一临时目录内逐项核对实际用途；截图、录像、回放、基准结果、当前测试证据、发布包、回滚版本、源码 / 一次性脚本、配置 / 凭据、环境、依赖、缓存数据库不因位于上述目录而自动适用。Unity `Library`、`.venv`、`node_modules`、`bin/obj` 不在默认范围。它们需专项策略。
- 默认隔离到仓库根目录的同级 `<仓库名>-cleanup-quarantine/<运行ID>/`，按原相对路径存放；发现该隔离目录是链接、非目录或用途冲突时停止该仓库，不覆盖。记录写入用户状态目录 `repo-cleanup/artifact-cleanup/<运行ID>/`。隔离区不纳入下一轮候选扫描。
- 普通日志采用上述直接删除规则，不进入隔离等待；删除后不能靠审计记录恢复正文。其他隔离内容至少保留 7 天，默认没有到期自动永久删除权限；用户明确授权永久删除时才在到期后核验清单再执行。审计和恢复记录默认保留，不自动轮转。报告须区分移出工作目录与实际释放空间。

## 判断与报告

1. 用 Git 区分已跟踪、未跟踪和被忽略内容。扫描明确临时目录时检查全部后代，不因父目录被忽略就整体判为垃圾。使用可安全处理空格、换行的路径读取方式，不解析供人阅读的命令输出后直接拼接删除命令。
2. 分类为中间数据、日志/截图、一次性脚本、可复用工具、正式成果或用途未知。记录路径、大小、时间及所属任务；引用相关项目说明、调用位置或配置作为证据，不复制凭据和文件正文到报告。
3. 按默认策略区分普通运行日志与任务批次，核对所需的结束证据、产物不再需要且未被使用、时间或数量阈值已满足。任务完成记录或用户明确指定可作为任务证据；“能重新生成”还需确认生成入口和输入仍存在。没有充分证据时列为待判断。
4. 对脚本检查代码、CI、文档和其他脚本中的调用及动态调用可能性；未搜索到引用不等于无用途。有复用价值时建议保留或整理，不擅自移动到正式工具目录。
5. 默认保护 Git 已跟踪内容、正式数据、凭据、环境配置、任务证据、配置中的保护项，以及未知内容。保护规则优先于允许路径和到期规则。目录含任何保护项或未知项，就不能整体处理。
6. 不跟随符号链接扫描或清理外部目标，不跨嵌套仓库、子模块、挂载边界或进入 Git 元数据。对链接本身单独报告；无法确认任务或进程已停止使用的文件，保留。

输出具体候选及理由，分别列出可处理、保留、待判断和失败项。请求扫描或评估时到此为止。请求执行清理或已有定期执行授权时，仅处理同时满足授权范围与上述证据的候选，不重复索要已提供的授权，也不把安装或调用技能当成无限制删除授权。

## 执行与恢复

- 两种清理技能共用仓库锁：以规范化的 Git common directory 绝对路径的 SHA-256 为键，在用户状态目录 `repo-cleanup/locks/` 中原子创建锁目录。macOS/Linux 使用 `${XDG_STATE_HOME:-$HOME/.local/state}`，Windows 使用 `%LOCALAPPDATA%`。记录本次运行 ID 和所有者；锁存在则跳过该仓库，不自动删除无法确认归属的锁。只释放本次获得的锁。
- 执行前重新检查 Git 状态、路径类型、保护规则、任务/进程状态及候选内容；对比扫描时的文件身份和内容摘要，任何变化都重新判断。父路径变为链接或出现新的文件时停止该项；锁只协调清理任务，不能阻止编辑器和其他进程写入。
- 普通日志按默认策略直接删除：先持锁、落盘 planned 审计记录，再复核文件身份、哈希和占用，删除后确认不存在并标记 deleted；失败逐项记录。其他候选默认选择已授权的隔离动作：先记录原始绝对路径、仓库、内容摘要、理由、时间、目标位置和 `planned` 状态，再移动到授权的隔离区，验证后标记 `quarantined`。隔离区必须在扫描范围外；跨文件系统时先完整复制并校验，再复核源文件后移除源文件，失败则保留源文件并记录部分结果。
- 执行前完成活动任务检查；仍可能并发写入且无法可靠隔离时跳过，不能把一次哈希检查当成持续无写入保证。禁止使用广泛的 `git clean` 或按名称批量 `rm`。
- 恢复时核对隔离内容与清单，原位置存在任何内容就停止该项，不能覆盖；恢复成功后更新记录。若上次执行中断，先核对原位置、隔离位置及记录状态，不重复移动或删除。
- 只有策略明确授权永久删除、保留期已过、隔离内容与清单一致且不处于恢复操作中，才删除对应隔离项；到期本身不产生删除授权。未恢复或未最终处理的记录不能随日志轮转丢弃，已完成记录按约定期限保留。
- 单仓库失败不阻塞其他仓库；权限、磁盘空间或记录写入失败时停止该项，保留可恢复现场。

## 结果与定期运行

报告每个仓库的已隔离、已删除、已恢复、保留、待判断、失败项及理由，给出清单位置和恢复方式。隔离只算移出工作目录的体积，不报告为已释放磁盘空间；永久删除体积也应区分逻辑大小与实际空间测量。

本技能定义一次由代理执行的流程，不附带无人值守删除程序。调度由现有调度器负责；仅在用户要求时配置周期与策略。定时运行采用同一默认轮转策略；临时批次缺少结束证据时保留，普通运行日志按本节相应条件检查，不因无人应答而扩大到日志策略之外的永久删除。
