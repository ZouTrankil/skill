# ast-grep 结构化搜索与重构

使用完整命令 `ast-grep`，不要使用可能与 Linux 系统命令冲突的 `sg`。先检查命令是否可用；缺失时按目标环境安装或说明阻塞。明确目标目录、语言、排除范围及项目的已有规则和工作区改动；先搜索命中范围，避免不经摸排就逐文件批量替换。

在 POSIX shell 中对包含 `$VAR` 等元变量的模式和替换内容使用单引号，避免 shell 展开；路径单独引用。若内容本身含单引号或使用其他 shell，采用该 shell 安全的引用方式。`--json` 仅用于只读查询和预览，不与 `-U` 同用。

## 搜索与预览

```bash
ast-grep run -p '<原代码模式>' -l <语言> '<目标目录>'
ast-grep run -p '<原代码模式>' -l <语言> --json=compact '<目标目录>'
ast-grep scan -r '<规则文件.yml>' '<目标目录>'
```

优先复用目标项目中适用的 YAML 规则。注意默认忽略规则、隐藏文件、语言识别及生成代码可能影响覆盖范围；按任务需要调整并说明。确认匹配的文件和数量，抽查上下文及未命中的写法。AST 模式只证明语法形状，不能证明调用实际绑定到目标 API；检查同名方法、作用域、类型、反射和动态调用，无法安全区分时缩小范围或手工处理。

## 改写与验收

只有任务授权修改时才写入。先不带 `-U` 预览改写 diff，检查范围和边界；预览可信且目标文件状态未发生变化后，再以相同范围写回：

```bash
ast-grep run -p '<原代码模式>' -r '<目标代码模式>' -l <语言> '<目标目录>'
ast-grep run -p '<原代码模式>' -r '<目标代码模式>' -l <语言> -U '<目标目录>'
```

规则包含 `fix` 时，同样先用 `ast-grep scan -r '<规则文件.yml>' '<目标目录>'` 预览，再按需使用 `-U` 写回。保留其他人的改动；若文件在预览后变化，重新检查并预览。审查实际 diff，重新搜索原模式和相关变体；仅对需要人工处理的局部文件做定向修改，不顺手格式化无关文件。执行项目适用的编译、类型检查或测试；无法运行时说明原因和未验证范围。

汇报使用的规则或模式、自动改写命中数和文件数、残留或需人工确认的边缘文件、验证结果。无法可靠统计时说明统计口径或未知，不推断数字。常用且确有跨项目价值的模式，经匹配与误匹配样例验证后可沉淀到本技能 `rules/`；项目专属规则留在项目中。
