# raw 增量同步

用于提供 `tools/sync_raw.py` 的记忆仓库。先读取该仓库 AGENTS.md 和 README.md；脚本归仓库维护，技能不复制另一套实现。

## 执行与进度

在 memory 根目录执行 `python3 tools/sync_raw.py --json`。也可传 `--root` 指定目录。脚本按文件内容哈希同步新增、修改、改名和删除，更新标签、数值及浏览页；不依赖文件日期或 Git 提交。无变化时不重复提取、不刷新已有进度。首次接管现有索引仅建立基线，不代表历史全部完成了长期认知评估。

读取输出的 `changes`、`errors` 和 `pending_reviews`。每份失败材料单独报告原因，成功文件可继续；错误文件待下轮重试。程序的 `indexed_files` 仅表示确定性索引完成，不能当作长期认知更新完成。

`index/sync-state.json` 保存成功处理哈希和语义评估队列。数值、标签等先写入，进度最后提交；脚本有并发锁及单文件原子替换，中断后重新执行即可。运行期间变化的输入不确认旧版本。不要人工把失败来源的哈希改为成功，不把 `--rebuild-values` 当成语义确认。

## 处理语义评估队列

- 只读队列涉及的来源及必要的相关实体/主题页；修改文件可读完整当前版本，不要求从字节偏移截取追加部分。
- 新增或修改：判断是否形成新的项目状态或长期结论。临时数据、计划和外部建议保留边界；没有长期变化也须留下“无需更新”的具体理由。
- 改名：检查实体/主题页中指向旧路径的引用，修复必要的链接，保留人工标注。
- 删除：报告受影响的来源及引用，将相关结论标为来源待核对；不自动删除长期结论，不猜测替代依据。
- 若来源日期已有 summary，报告它可能需要复核；不覆盖该 summary，也不重新推送旧日期通知。不能把 `summary_may_be_stale` 当作正文已更新的证明。
- 完成该版本的评估和必要写入、链接核对后，运行 `python3 tools/sync_raw.py --ack 'raw/实际路径.md' --sha256 '队列中的哈希' --note '更新了什么，或为何无需修改长期结论' --json`。脚本验证来源及队列版本；确认失败时重新同步，不强行清队列。队列可分批完成，未评估项保留至下轮。

## 定时任务

原任务的 precheck 应调用 `python3 tools/sync_raw.py --precheck`。它先同步索引，再按 Asia/Shanghai 的昨天判断复盘是否存在；有语义待办、错误需处理或复盘待做则返回 0，无事可做返回 1。预检查输出是同步结果，不等于复盘或通知完成。

任务提示词仍须要求正式运行时再次同步，因为手动“立即运行”会绕过预检查。只在完成索引同步与语义评估后检查复盘是否存在；存在则仅跳过复盘和通知。保持现有通知授权与失败处理规则，不因索引更新发送通知，不自行提交、推送或配置额外定时器。
